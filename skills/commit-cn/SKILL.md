# commit-cn

使用中文提交信息提交代码变更，遵循项目的提交规范（feat/fix/refactor等前缀 + 作用域 + 描述）

**适用场景**: 当用户要求提交代码、添加提交备注，或在中文项目中进行代码提交时使用

**触发短语**: "提交代码"、"commit"、"提交这个改动"、"添加提交备注"

---

## 工作流程

当用户请求提交代码时，按以下步骤执行：

### 1. 检查当前状态

运行以下命令了解代码状态：

```bash
# 查看已暂存和未暂存的变更
git status
```

### 2. 分析变更内容

基于 git status 输出，识别：
- **变更类型**：新功能(feat)、修复(fix)、重构(refactor)、文档(docs)、测试(test)等
- **影响范围**：哪个模块/组件受到影响（用于scope）
- **核心目的**：这次变更解决了什么问题或添加了什么功能

### 3. 生成提交信息

遵循以下格式：

```
<type>(<scope>): <subject>

[可选的详细描述]
```

**类型(type)**：
- `feat`: 新功能
- `fix`: 修复bug
- `refactor`: 重构（不改变功能）
- `docs`: 文档变更
- `test`: 测试相关
- `chore`: 构建/工具变更

**作用域(scope)**：
- 使用中文描述受影响的模块，如：`hangup`、`autodialer`、`callback`等

**主题(subject)**：
- 使用中文简洁描述变更内容
- 不超过50个字符
- 说明"做了什么"和"为什么"

**示例**：
```
feat(hangup): 挽单结果中添加config字段传递

在HangupHelper.buildHangupResult方法中设置config字段，确保挽单结果包含号码配置信息
```

```
fix(callback): 修复意向回调空指针异常

添加null检查避免在处理回调数据时出现NPE
```

### 4. 执行提交

**重要：必须按照以下顺序执行，不能颠倒！**

**步骤 1：添加到暂存区**

如果有未暂存的变更，先添加到暂存区：

```bash
# 添加特定文件（优先使用，避免意外提交敏感文件）
git add path/to/file1.java path/to/file2.java

# 或添加所有变更（谨慎使用）
git add .
```

**步骤 2：提交到本地仓库**

使用HEREDOC格式提交（确保格式正确）：

```bash
git commit -m "$(cat <<'EOF'
<type>(<scope>): <subject>

[可选的详细描述]
EOF
)"
```

**步骤 3：推送到远程仓库**

提交成功后，推送到远程：

```bash
git push origin <current-branch>
```

**步骤 4：验证结果**

推送后验证：

```bash
git status
```

**⚠️ 关键提示**：
- 必须先 `git add`，再 `git commit`，最后 `git push`
- 不能先 push 再 commit，这会导致 push 失败（因为没有新提交）
- 使用单个命令链接：`git add ... && git commit ... && git push ...`

### 5. 输出结果

向用户报告：
- 提交是否成功
- 提交的哈希值
- 提交信息内容
- 推送状态（是否成功推送到远程）

## 注意事项

### 安全规范
- ❌ **禁止**使用 `git add -A` 或 `git add .` 除非明确所有文件都应该提交
- ❌ **禁止**提交敏感文件（.env、credentials.json等）
- ❌ **禁止**使用 `--amend` 除非用户明确要求
- ❌ **禁止**使用 `--no-verify` 跳过钩子
- ✅ **优先**使用具体文件路径添加到暂存区

### 提交信息质量
- 使用中文描述，清晰准确
- 遵循项目现有的提交风格（通过git log学习）
- 主题行简洁，详细信息放在正文
- 说明"为什么"而不仅仅是"做了什么"

### 工作流程
- 只在用户明确要求时才提交
- 如果不确定应该提交什么，先询问用户
- 提交前展示将要使用的提交信息，让用户确认
- 提交后验证状态

## 示例对话

**用户**: "帮我提交该代码，并添加提交备注"

**助手行为**:
1. 运行 `git status`
2. 分析变更：发现修改了 HangupHelper.java，添加了config字段设置
3. 生成提交信息：`feat(hangup): 挽单结果中添加config字段传递`
4. 执行提交
5. 报告结果：提交成功，哈希值，提交信息
