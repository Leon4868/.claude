# Figma 浏览器 UI 验收

设计师只需提供 Figma 链接和环境页面链接。自行读取设计、寻找对应页面与状态、完成可安全执行的浏览器操作，再交付便于设计师和开发一起查看的报告。无需项目源码、选择器、账号密码或手写测试用例。

## 输入与范围

- 必需：Figma 链接、环境页面链接。可选：画板名称、进入路径、语言、主题、视口和容差。
- 链接指向画板时，验收该画板、明确连接的原型/组件变体状态，以及对应页面范围内的只读交互。按入口直接关联的节点补取设计，不扩展到仅因名称相似的其他业务画板。指向组件时，只检查组件在页面中的对应实例；不能把组件尺寸当作页面视口。
- 链接指向 Figma 页面或整个文件时，先读取画板清单，再根据线上页面的标题、导航和内容匹配相关画板。匹配唯一时直接继续；有多个合理候选时，列出候选名称并只询问验收范围。不得默认为整个设计文件。
- 从页面可见导航和控件寻找弹窗、抽屉、页签等进入路径；只有无法安全到达或匹配存在歧义时才询问设计师。
- 给出简短开工摘要：设计画板 → 页面 → 状态 → 视口。后续连续执行，无需逐步确认。

## 连接与操作边界

先发现当前可用的 Figma 与浏览器工具，按其实际文档和参数调用。工具名称、参数及权限以本次会话为准。连接细节见 [references/tool-routing.md](references/tool-routing.md)。

**已登录页面的 URL 不携带登录态。** 优先复用工具可见的现有登录会话，核实页面确实呈现登录后内容。找不到对应会话时，请设计师将该页面在可连接的浏览器中打开；出现登录页时请其自行登录。继续完成不依赖登录的设计取数。

默认对业务数据只读。允许导航、滚动、悬停、聚焦、切换页签、只读筛选和翻页、打开并关闭弹窗或下拉。输入仅限明确的查询字段；编辑表单只观察现有值。保存、提交、删除、发送、上传、发布、购买、改变设置及可能自动保存的控件，需要用户明确授权对应操作。必须创建数据才能出现的状态列为未覆盖，继续其余画板。

通过真实界面到达状态。不得改 DOM、注入样式、伪造接口数据来凑出设计效果。脚本只用于当前工具明确支持的只读测量。工具定位失败先重新获取页面结构；定位失败本身不能判成产品缺陷。

截图和输出只保留验收所需内容；采集时优先裁剪或工具支持的遮罩。敏感区域无法排除时跳过该截图并说明原因。不要导出 Cookie、Token、浏览器存储或完整请求头。链接去掉凭证和敏感参数；不要保存 Figma 临时签名下载地址。

## 建立可比较的基准

**常规最短路径**：从链接解析 node ID → 一次取得画板 metadata 和截图 → 在用户现有登录浏览器中读取目标页正文 → 记录浏览器尺寸和页面状态 → 按交互清单执行只读路径 → 写 `results.json` → 运行报告生成器。页面读取失败时先按 [工具连接和取数](references/tool-routing.md) 的确定性回退检查现有 Chrome；不要只凭 DevTools 不通或标签页清单就写受阻报告。已取得的设计截图、实页截图和交互结果在同次任务内复用。

1. 读取目标节点、画板尺寸、设计截图和关键元素属性。用 metadata 确认范围，用设计属性、标注或绑定变量取得数值。变量清单不等于元素最终样式，截图不能证明精确字号或颜色。取不到的值写“未知”。
2. 优先使用当前 Figma 工具提供的设计属性；需要 `get_design_context` 或 `use_figma` 时，先加载工具要求的 Figma 指引，并将操作严格限制在读取设计。具体取数方法见工具参考。
3. 记录每个画板的 URL、node ID、宽高、状态，以及页面的最终地址、语言、主题、视口 CSS px、DPR、浏览器缩放和时间。Figma 截图缩放比例单独记录。
4. 先区分**网页视口**和**浏览器外窗**。常规设计比较匹配网页视口宽度；用户明确要求整个浏览器尺寸时，调整并核实外窗 bounds，保留 Chrome 工具栏占用的高度，不把外窗 1440×900 写成网页视口 1440×900。若浏览器工具仅支持视口覆盖，不用它冒充外窗调整；需要 AppleScript 等系统控制时按当前工具权限要求和用户授权执行。长页面画板的高度属于内容高度，分段滚动并记录偏移。弹窗/组件稿用对应页面视口比较局部。不能取得完全相同的网页视口时，保留实际尺寸并写明比较限制。
5. 截图前等待目标元素出现、字体与相关图片加载、骨架屏消失和布局稳定；不要依靠固定长时间等待。无法稳定则记录环境问题。

证据存入当前任务允许的交付目录，例如 `outputs/ui-acceptance-YYYYMMDD-HHmm/`，下设 `design/`、`actual/` 和 `measurements/`。中间草稿放 `work/`。

## 执行验收：先走交互，再细测差异

默认执行完整的只读 UI 走查。只提供两个链接也应自行发现可安全到达的状态，不能把默认截图当作验收完成。开始操作前读取 [references/interaction-coverage.md](references/interaction-coverage.md)，并按 [references/report-format.md](references/report-format.md) 建立 `schemaVersion: 2` 的结果文件。

1. **建立清单**：复用一次设计结构读取和页面快照，列出设计中的状态，以及范围内的下拉、筛选、查询、页签、分页、滚动、弹窗/抽屉入口；将每个验收目标写入 `targets`，将准备执行的转换写入 `interactions`。同一入口通向多个设计状态时分别列出。对话框中发现的新控件追加到清单。
2. **走完只读路径**：默认态截图后，优先完成打开/关闭、切换、筛选、查询、分页与滚动等真实操作，并验证可见结果。动态交互不以“设计是否画出每个展开态”为前提；没有设计依据的展开态只能证明操作与页面表现，不能声称设计还原一致。
3. **取证与检查**：每次状态转换保存操作、可观察预期、实际结果、前后证据及还原结果。用页面结构验证变化，在视觉关键状态或差异处截图。共享默认截图可重复引用；不为每次聚焦重复整屏截图。
4. **集中测量**：交互路径完成后，对八类项目中的差异和关键元素批量取数。每次只读取一个局部区域的必要属性，不导出整页 DOM。相关颜色、文字和几何属性在同一次读取中取得，重复组件使用代表样本；异常样本单独补验。
5. **逐项收口**：对照清单检查每个目标是否有已验证、差异、不适用或具体的未覆盖/受阻记录。未执行的转换继续执行；缺样本或权限等硬性条件无法满足才留缺口。每条独立路径结束即还原现场并写入结果文件，后续恢复运行从未完成项开始。

八类项目：`布局与尺寸`、`间距与对齐`、`字体与文字`、`颜色与表面`、`图标与图片`、`内容与溢出`、`组件状态`、`交互与滚动`。每类记录“一致 / 有差异 / 未覆盖 / 不适用”，并保留简短依据或原因。检查细节见 [references/comparison.md](references/comparison.md)。

- 同一元素先对齐其语义、状态和容器，再比较数值。位置转到同一局部坐标系；相邻元素的间距由矩形边缘相减，不能拿 margin 代替实际距离。
- 使用页面结构中的真实元素进行测量；只在工具允许时使用 `scripts/measure.js`。无测量能力时可以给出“目测发现”，精确数值标未知，相关数值项目列为未覆盖。
- 默认几何容差为 1 CSS px；文字、字号、字重及确认后的颜色按设计值比较。用户给定的容差优先。像素抗锯齿、截图缩放和不同数据不自动算缺陷。不要计算虚构的“还原度百分比”。
- 设计静态文案逐字核对；线上姓名、日期、计数等业务数据不要求与样例相同，检查其格式、占位、溢出及布局表现。
- 设计明确展示或标注的状态都应覆盖；范围内控件的安全交互也要实际执行。两类目标分别标记来源“设计”或“页面观察”。没有设计依据时只记录可观察行为，不编造样式预期。提交等业务写入不在默认范围，不作为只读走查缺口。
- 同一原因造成的重复问题合并，列出受影响位置；每个被认定的差异要有设计依据和实际证据。

每条问题写：画板、状态、用户可见的元素位置、属性、设计值、实际值、证据方式（测量/目测）、影响、严重度（阻断/明显/细微）和可操作的修改建议。建议描述设计目标，不猜代码根因。

## 控制耗时与断点续验

- 先用一次轻量页面读取确认连接，再取设计和默认态；连接不通时不要先花大量时间细测设计。设计、截图与已完成测量在同次任务内复用；设计链接/节点或版本变化时再刷新受影响部分。
- 同一页面内连续执行已确定的安全步骤，每个会改变下一步定位依据的状态仍需检查。独立的设计取数和本地报告处理可以并行；同一浏览器的交互串行，避免互相覆盖现场。
- 一个区域一次批量测量，优先约 10～20 个必要元素。读取超时则缩小范围，不重发更大的脚本。不要反复截同一状态、下载同一设计图或全页轮询。
- 当前连接失败时，按工具参考中的已知连接路径做一次有依据的恢复；若 Chrome 调试连接不可用，但原生可访问性仍能读取同一登录窗口，则继续可验证的只读交互和截图，将 DOM 样式与精确矩形列为未覆盖。只有所有已支持的页面读取路径都不能取得目标页正文时，才把页面判为受阻。不要换浏览器、重启、改调试配置来碰运气。连接恢复后检查现场和原始尺寸，再继续缺口，不重做已完成路径。
- 用可见目标、加载提示消失及相关布局稳定作为等待条件；不固定长时间等待，不要求持续轮询页网络空闲。超过工具的有界等待记录现象后继续独立路径。
- 记录实际阶段耗时和调用数（工具可提供时），在报告中说明耗时来自连接、设计取数、页面交互还是报告处理。不承诺固定分钟数，也不靠减少已选范围来提速。

## 判定与交付

画板结论：

- `一致`：八类均已检查或有理由不适用，适用项有足够证据，且无差异。
- `有差异`：适用项完成检查，至少有一个有依据的差异。
- `未覆盖`：部分状态、关键属性或数据样本没有验证。已经发现的问题仍保留，不能因存在差异而掩盖覆盖缺口。
- `受阻`：该画板无法开始有效比较，例如缺设计权限、登录失效或环境不可达。

按 [references/report-format.md](references/report-format.md) 写 `results.json`。生成单文件离线报告：

```sh
node <skill目录>/scripts/render-report.mjs --input <证据目录>/results.json --output <证据目录>/ui-acceptance-report.html
```

总结论由脚本计算：`PASSED`（已验范围一致）、`HAS_DIFF`（完成检查且有差异）、`PARTIAL`（有有效比较但存在未覆盖/受阻）、`BLOCKED`（尚无有效比较）。通过只代表本次选定范围，不能泛化为全站通过。

报告含画板和状态覆盖、交互清单及前后证据、设计与实页并排截图、可搜索的差异清单、严重度、修改建议、未覆盖原因、环境与测量记录。生成器校验目标均有交互记录，完成记录有前后证据；动态清单有缺口时不能输出完成结论。展示正文使用设计师能看懂的元素名称。

收尾时恢复工具改变的视口、滚动位置及临时模拟设置，关闭自己打开的临时弹窗和标签页；保留用户原有标签页。用户明确要求保留的浏览器外窗尺寸不恢复。无法恢复的项目记入报告。

最终回复用中文写总结论、验收范围、问题数量、最重要的问题、未覆盖原因和报告链接；同时说明执行了真实浏览器操作还是仅做设计/工具预检查。

调用示例：

```text
使用 $figma-ui-acceptance 做 UI 验收。
Figma：<设计稿链接>
线上页面：<已登录浏览器中的页面链接>
```
