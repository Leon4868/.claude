# UI 验收（设计稿 ↔ 页面）

面向 UI 同事的独立验收流程。不依赖任何项目代码；只读页面，不修改业务数据，也不修改代码。

## 0. 开工前确认（缺什么问什么，已给出的不再问）

1. **设计稿链接**：Figma 链接需带 `node-id`（画板或页面）；蓝湖链接需带 `tid`、`pid`、`image_id`。一个链接对应一个画板。给的是整页或整个项目时，先列出画板清单，请对方选定本次范围。
2. **页面地址**：每个画板对应的页面 URL；如果需要先点开某个弹窗、抽屉、页签才能看到，请对方说明进入路径。
3. **环境与登录**：使用对方已登录的 Chrome。遇到登录页时停下，请对方自己登录，绝不代填账号密码。
4. 确认后输出开工摘要：画板 → 页面/状态 → 进入路径，然后连续执行，不再逐步确认。

## 1. 安全边界

- 允许：打开页面、切换页签/筛选、翻页、悬停、打开弹窗/抽屉/下拉以到达设计稿画到的状态，结束后**取消或关闭**。
- 禁止：点击保存、提交、删除、发布、发送，也不改页面数据。如果某个状态必须造数据才能看到，就标为「受阻」并说明原因，不要自己去造。
- 禁止：注入脚本去改 DOM、样式或接口返回来“凑出”某个状态；也不要改业务代码。
- 截图或报告里出现手机号、token、webhook 等敏感信息时，先裁掉或打码再保存；报告里不放敏感原文。

## 2. 准备

1. 证据目录：`<当前工作目录>/ui-acceptance-<YYYYMMDD-HHmm>/`，其下建 `design/`、`actual/`。所有截图都存到这里。
2. 设计稿基准（详见 [design-sources.md](references/design-sources.md)）：
   - Figma：`get_metadata` 取画板尺寸和元素位置；`get_screenshot`（`maxDimension` 设为画板宽高中较大的值）取截图，并用 curl 下载到 `design/`；`get_variable_defs` 取颜色、字体变量。**不要**调用 `get_design_context`（那是生成代码用的）。
   - 蓝湖：`get_design_context(url)` 一次拿到 HTML+CSS 标注、design tokens 和预览图，预览图存到 `design/`。
   - 取不到设计数据时，标为「受阻」，不凭经验猜数值。
3. 视口：用 chrome-devtools 打开页面，先记录原来的 `innerWidth/innerHeight/devicePixelRatio`，再用 `resize_page` 调成画板尺寸（常见 1440×900）。全部完成后恢复原尺寸。

## 3. 逐画板执行

每个画板按以下顺序做：

1. **到达状态**：导航 → 按进入路径交互 → 等目标元素出现、加载动画结束（等可观察的具体条件，不要固定长时间 sleep）。
2. **整屏对比**：`take_screenshot` 存到 `actual/<画板ID>.jpeg`，与设计稿截图并排看，找出肉眼可见的差异区域。
3. **数值核对**：对差异区域和关键元素（标题、按钮、表头、输入框、标签、卡片），用 `take_snapshot` 拿到元素 uid，再用 `evaluate_script` 运行 [measure.js](scripts/measure.js) 取计算样式（CSS px）。拿去和设计标注比，不要用截图像素去量。
4. **逐项记录**：每处差异记一条：元素、属性、设计值、实际值、严重度；需要时附元素级截图（`take_screenshot` 传 `uid`）。判定规则和检查清单见 [checklist.md](references/checklist.md)。
5. **还原现场**：关闭弹窗、抽屉，取消未保存的内容，再进入下一个画板。

画板结果分四种：`一致`、`有差异`、`未覆盖`（设计稿画了，但页面上缺样本或缺状态）、`受阻`（权限、登录、环境问题，或必须造数据才能看到）。工具定位失败不算页面问题，要先换方式重新定位。

## 4. 产出

1. 写 `results.json`（结构见 [report-format.md](references/report-format.md)），放在证据目录里，截图路径写相对路径。
2. 生成离线报告：
   ```sh
   node <skill目录>/scripts/render-report.mjs --input <证据目录>/results.json --output <证据目录>/ui-acceptance-report.html
   ```
   总结论由生成器自动计算，不要手填。
3. 最终回复只写摘要：总结论（`PASSED / HAS_DIFF / PARTIAL / BLOCKED`）、各画板结果、阻断和明显差异的清单（元素、设计值、实际值）、未覆盖/受阻的原因、报告路径。细微差异只报数量，详情留在报告里。
4. 收尾：恢复视口尺寸，关闭自己新开的标签页，不关对方原来的标签页。
