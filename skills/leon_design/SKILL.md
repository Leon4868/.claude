# Leon Design · UI项目设计方法

把课程方法转成当前项目的设计决策与可用成果。默认用中文简洁交流，以具体问题、改动和证据说明结果。

## 先定位任务

查看用户提供的页面、项目代码、设计稿与已有组件，确定页面任务、用户、平台、主要操作及状态。能从项目推断的直接采用；只对会影响方案的缺失信息提问，同时继续独立工作。

优先延续现有品牌、组件和技术约束。课例中的黑白灰、3D、IP等是可选手法，不是所有产品的统一答案。局部优化不扩大成整站重做。

## 项目中的执行方法

1. **先结构，后风格。** 去掉装饰检查信息分组、阅读顺序、间距与主要操作。按容器定位影响最大的模块，保留已成立的部分。主形象可以是图标、卡片、图表或角色。
2. **先母版，后体系。** 在一个关键页面或一枚素材上确立造型、配色、材质、视角和光照，再延展。图标检查大小、圆角、语言、粗细、疏密、间距、比例、正负形、角度；角色检查特征、风格、表情、视角和动作。
3. **先重点，后细节。** 明确第一视觉焦点，降低辅助区域的竞争。必要时用灰度、缩小预览、并排对照检查明暗与体量；投影、边缘光、反光围绕同一空间关系精修。
4. **把AI用于受控探索。** 区分结构参考与质感参考，先固定要保留的部分，再更改一个具体变量。不能只写“高级、好看”。既有SVG、组件或代码能直接完成时沿用项目方式；需要位图素材时使用可用的图像生成能力，再回到界面验收。
5. **交付实际成果。** 用户要求实现时完成代码或可用设计产物，不停在建议。根据任务范围检查真实页面、关键状态和目标尺寸；图标、插画大图漂亮，不代表缩小后可用。

## 改版与提案的证据

- 原版与改版按同一任务、同一状态、同一尺度比较，不把原版刻意变差。
- 保留核心功能与业务语义；装饰不能吞掉操作、警示或重要数据。
- 提效从具体方向找证据：少操作步骤、自动展示所需信息、更易读的可视化、更有效的屏幕信息承载、减少干扰。不能把“换了颜色”写成体验提升。
- 组织讲述时用：问题与依据 → 设计方向 → 执行改动 → 验证与反馈。没有数据就说明预期和验证办法，不编造业务提升。
- 放大一两处最有价值的细节；本体精度不够时先精修，包装不能替代设计质量。

## 输出

默认先展示完成的设计或实现，再用少量文字解释关键变化、原因与验证结果。评审任务给出按影响排序的问题和具体改法，注明页面区域或代码位置。仅报告实际检查过的内容和仍未解决的限制，不复述整套课程。
