# 需求归档工具

## 用途

将已上线的需求文件夹从根目录归档到 `archive/{当日日期}/` 目录下，保持工作区整洁。

## 触发时机

当用户要求"归档需求"、"整理需求"、"清理已上线需求"等类似请求时使用。

## ⚠️ 重要：交互式执行规范

本 skill 的所有功能都使用 AskUserQuestion 工具进行交互式操作。Claude 在执行时必须：
1. 使用 AskUserQuestion 让用户选择要执行的操作
2. 在执行归档前必须让用户确认
3. 不要未经确认直接移动文件

## 参数处理

### 快捷命令支持

当用户使用 `/archive-requirements <command>` 格式时：

- 无参数 → 交互式选择要归档的需求
- `list` → 查看已归档的需求列表
- `all` → 归档根目录下所有需求文件夹

## 项目约定

### 工作目录

需求文档项目根目录：`C:\Users\54542\tapd-requirements`

### 需求文件夹命名规则

```
{TAPD_ID}_{需求名称}_{版本日期}
```

示例：`1135238004001009043_智能任务统计分析增加聚合维度分析_20260312`

- TAPD_ID：TAPD 需求 ID（数字）
- 需求名称：中文描述
- 版本日期：8 位数字，格式 YYYYMMDD

### 归档目录结构

归档目录以**归档当天的日期**命名（格式 YYYYMMDD），不是需求的版本日期。

```
tapd-requirements/
├── archive/
│   ├── 20260319/                     # 2026-03-19 归档的需求
│   │   ├── 1135238004001009043_智能任务统计分析.../
│   │   ├── 1135238004001009083_财务对账菜单.../
│   │   ├── 1135238004001009105_语音助手.../
│   │   └── 发版文档_release_20260319.md
│   ├── 20260402/                     # 2026-04-02 归档的需求
│   │   ├── ...
│   │   └── 发版文档_release_20260402.md
│   └── ...
├── doc/                    # 归档后对应文档会被移走
├── （进行中的需求文件夹留在根目录）
└── .claude/
```

### 发版文档处理

发版文档位于根目录下，命名格式为 `发版文档_*.md`（如 `发版文档_release_20260319.md`）。

归档时，将根目录下所有 `发版文档_*.md` 文件一起移入当天的归档目录 `archive/{当日日期}/`。

注意：历史遗留的发版文档可能在 `doc/` 目录下，归档时也一并检查并移入。

## 工作流程

### 功能一：交互式归档（默认）

#### 步骤 1：扫描需求文件夹

扫描根目录下符合命名规则的需求文件夹（排除 `archive`、`doc`、`.claude` 等非需求目录）。

```bash
cd "C:\Users\54542\tapd-requirements"
ls -d */
```

识别规则：文件夹名匹配 `{数字}_{中文}_{8位数字}` 格式。

#### 步骤 2：展示并让用户选择

使用 AskUserQuestion 展示扫描到的需求文件夹，让用户多选要归档的：

```json
{
  "questions": [{
    "question": "选择要归档的需求文件夹",
    "header": "扫描到以下需求文件夹",
    "multiSelect": true,
    "options": [
      {"label": "智能任务统计分析增加聚合维度分析", "description": "ID: 1009043 | 版本: 20260312"},
      {"label": "财务对账菜单新增上月月终账户余额等", "description": "ID: 1009083 | 版本: 20260319"},
      {"label": "语音助手分写入...", "description": "ID: 1009105 | 版本: 20260319"}
    ]
  }]
}
```

选项的 label 使用需求名称（从文件夹名提取），description 显示短 ID 和版本日期。

#### 步骤 3：执行归档

获取当天日期（格式 YYYYMMDD），对用户选中的每个需求文件夹：

1. 创建归档目录（如果不存在）：`archive/{当日日期}/`
2. 移动需求文件夹到归档目录
3. 检查根目录下是否有发版文档（`发版文档_*.md`），如有则一起移入
4. 检查 `doc/` 下是否有历史遗留的发版文档，如有也一起移入

```bash
cd "C:\Users\54542\tapd-requirements"

# 获取当日日期
TODAY=$(date +%Y%m%d)

# 创建归档目录
mkdir -p "archive/$TODAY"

# 移动需求文件夹
mv "1135238004001009083_财务对账菜单新增上月月终账户余额等_20260319" "archive/$TODAY/"

# 移动根目录下的发版文档（如果存在）
for f in 发版文档_*.md; do
    [ -f "$f" ] && mv "$f" "archive/$TODAY/"
done

# 移动 doc/ 下的历史遗留发版文档（如果存在）
for f in doc/发版文档_*.md; do
    [ -f "$f" ] && mv "$f" "archive/$TODAY/"
done
```

#### 步骤 4：输出归档结果

归档完成后，输出简洁的结果摘要：

```
归档完成（20260319）：
- 3 个需求文件夹
- 1 个发版文档
```

### 功能二：查看归档列表（list）

扫描 `archive/` 目录，按归档日期展示已归档的需求：

```bash
cd "C:\Users\54542\tapd-requirements/archive"
ls -d */
```

输出格式：

```
已归档需求：

📁 20260319（3 个需求）
  - 智能任务统计分析增加聚合维度分析 (1009043)
  - 财务对账菜单新增上月月终账户余额等 (1009083)
  - 语音助手分写入... (1009105)
  - 发版文档_release_20260319.md
```

### 功能三：全部归档（all）

与交互式归档流程相同，但跳过选择步骤，自动选中所有需求文件夹。

仍然需要在执行前展示归档计划并让用户确认：

```json
{
  "questions": [{
    "question": "确认归档以下所有需求？",
    "header": "即将归档 3 个需求文件夹",
    "multiSelect": false,
    "options": [
      {"label": "确认归档", "description": "将 3 个需求文件夹移入 archive/{当日日期}/"},
      {"label": "取消", "description": "不执行任何操作"}
    ]
  }]
}
```

## 边界情况处理

### 根目录无需求文件夹

如果扫描后没有找到任何需求文件夹，直接告知用户：

```
根目录下没有找到需求文件夹，无需归档。
```

### 同一天多次归档

如果 `archive/{当日日期}/` 目录已存在（当天已归档过），直接将新的需求文件夹移入该目录。

### 发版文档已被归档

如果发版文档已经在 `archive/` 某个目录中存在，跳过移动，避免覆盖。

### 文件夹名不符合规则

跳过不符合 `{数字}_{文字}_{8位数字}` 命名规则的目录（如 `doc`、`archive`、`.claude`、`temp` 等）。

## 注意事项

1. 归档操作是移动（move），不是复制，归档后根目录不再保留原文件夹
2. 归档前务必确认需求已上线，避免误归档进行中的需求
3. `.claude/settings.local.json` 等配置文件随需求文件夹一起移动
4. 归档目录以当天日期命名，同一天归档的需求放在同一个目录下
