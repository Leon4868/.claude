# N4: 审查收尾

每个 task 完成后必须执行，按**单个 task 粒度**处理：风险评估 → 审查 → 标记完成 → QA 决策，一次走完。

进入 N4 前必须拿到 N3 输出的「变更文件清单 + 验证结果 + 待审重点」。如果无法区分本 task 改动和用户已有改动，先暂停确认，不得审查整个 working tree 后直接标记完成。

## 1. 风险评估（一次评估，供 Codex Review 和 QA 共用）

命中以下任一项即为**高风险 task**：

- 认证/授权/支付逻辑
- 数据库 migration 或数据模型变更
- API/接口契约变更（含前后端契约同时变更）
- 跨前端项目或跨后端 Maven 模块变更
- 当前 task 是该 feature 的最后一个未完成 task
- 距上次 QA 已累积 ≥5 个 task

均未命中 → 低风险 task。输出判定结果和理由。

## 2. AI 自审（所有 task 必做）

检查本 task 变更的：

- 代码质量：命名、结构、可读性、是否符合 `.claude/rules/`
- 逻辑正确性：边界条件、错误处理、并发安全
- 安全性：硬编码密钥、`.env` 误入 git、注入漏洞、OWASP Top 10
- 性能：N+1 查询、不必要的重复计算、内存泄漏风险
- 项目边界：变更是否只落在 N2/N3 定位的前端项目或后端 Maven 模块内
- 架构一致性：是否符合架构画像中的前端封装约定或后端分层约定

发现问题立即修复，不确定则暂停。

## 3. Codex Review（仅高风险 task）

- 低风险 task 跳过本步，记录「跳过 Codex review: 低风险」
- 高风险 task 调用 `codex:review`，传入**本 task 涉及的变更文件 diff**（不是整个 working tree），要求审查代码质量、逻辑缺陷、安全问题
  - 合理建议 → 修复后重新提交复审
  - 误报 → 记录理由后忽略
  - 如果当前环境无法调用 `codex:review`，必须说明原因，并执行一次等价的本地严格自审；高风险任务不得仅靠简略自审放行

## 4. 验证

N3 已运行过基准验证。仅当步骤 2/3 产生了代码修复时，按架构画像「验证命令」重跑一次；无修复则沿用 N3 结果。

审查与验证全部通过后方可进入步骤 5。

## 5. 标记完成（强制，不可跳过）

遗漏会导致断点恢复时重复执行任务。

1. 用编辑工具打开 tasks.md，将当前任务 `- [ ]` 改为 `- [x]`，**仅改 checkbox，不改其他内容**
2. **立即验证**：改完后重新读取 tasks.md，确认已标记为 `[x]`
3. 如果当前 feature 所有未作废任务均已 `[x]`，更新 `{SPECS_DIR}/PLAN.md` 中该 feature 状态为 `已完成`（无 PLAN.md 则跳过）

约束：

- 每完成一个 task **立即标记**，不批量、不延后
- 编辑失败则重试；仍失败时暂停，不得继续下一个 task
- 清理上下文之前必须确认标记已写入
- `[DROPPED]` 任务不改为 `[x]`，保持作废标记
- `[CHANGED]` / `[NEW]` 任务完成后只改 checkbox，不删除标签，保留变更历史

**LESSONS.md**：如有值得记录的内容（架构决策及理由、踩坑记录、跨 feature 影响、环境/依赖特殊处理）追加到 `{SPECS_DIR}/LESSONS.md`，格式 `## {日期} — {Feature名} / {Task标题}`；不记录常规开发和显而易见的事情。N3/N4 记录的验证阻塞、环境限制、接口契约变化必须写入，不要只在最终总结里口头说明。

## 6. QA 决策

- **高风险 task 或 feature 全部完成** → 派发 `leon-qa-engineer` subagent（定义在 `~/.claude/agents/`），prompt 传齐 **specs 路径、要验证的 feature/task 范围、代码项目路径、本次涉及的具体项目/模块清单、需要核验的接口契约/路由/页面入口/SQLMap 或配置文件**。subagent 内部加载同名 skill，回报「测试结果 + 逐条 AC 核验 + bug 清单」。上下文极少或仅需轻量核验时，可在主流程 inline 调用 `leon-qa-engineer` skill。
- **低风险 task** → 跳过 QA，输出跳过理由供追踪。

QA 通过 → 继续下一个 task（或 feature 完成流转）。
QA 发现问题 → 回流到 N3，由对应开发工种修复后重新执行 N4；最多 3 轮。超过 3 轮仍未通过时暂停，输出 bug 清单、失败验证、建议处理路径（此时额外上报一次 `--status paused`）。

## 输出进度

```text

🔍 风险: {高/低} | AI 自审: {结果} | Codex review: {通过/已修复/跳过/不可用}
🧪 QA: {触发+结果 / 跳过: 理由}
📊 Feature {done}/{total} | 总体 {done_f}/{total_f}
```
