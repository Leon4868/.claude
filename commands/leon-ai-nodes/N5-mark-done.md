# N5: 标记完成

**强制，不可跳过。** 遗漏会导致断点恢复时重复执行任务。

## 步骤

1. 确认 N4 输出 `允许标记完成: 是`；否则不得进入本节点
2. 用编辑工具打开 tasks.md，找到当前任务对应的行
3. 将 `- [ ]` 改为 `- [x]`，**仅改 checkbox，不改其他内容**
4. **立即验证**：改完后重新读取 tasks.md，确认该任务确实已标记为 `[x]`
5. 如果当前 feature 所有未作废任务均已 `[x]`，更新 `{SPECS_DIR}/PLAN.md` 中该 feature 状态为 `已完成`（无 PLAN.md 则跳过）

```diff
- - [ ] T-007: 安装依赖 ~5min
+ - [x] T-007: 安装依赖 ~5min
```

## 关键约束

- 每完成一个 task **立即标记**，不批量、不延后
- 编辑失败则重试；仍失败时暂停，不得继续下一个 task
- `/clear` 之前必须确认标记已写入
- `[DROPPED]` 任务不改为 `[x]`，保持作废标记
- `[CHANGED]` / `[NEW]` 任务完成后只改 checkbox，不删除标签，保留变更历史

## LESSONS.md

如有值得记录的内容（比如遇到的坑啊、难点啊、封装啊）追加到 `{SPECS_DIR}/LESSONS.md`：

- 架构决策及理由、踩坑记录、跨 feature 影响、环境/依赖特殊处理

不记录常规开发、显而易见的事情。格式：`## {日期} — {Feature名} / {Task标题}`

如果 N3/N4 记录了验证阻塞、环境限制、跨 feature 影响、接口契约变化，必须写入 LESSONS.md 候选；不要只在最终总结里口头说明。
