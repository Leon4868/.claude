# 话术文案批量修改工具 —— 前端实现方案（ai-admin-ui）

> 基于 TAPD 变更【20260819】重写。上一版按「工具页内同步弹窗」组织，已作废。

## Context

TAPD #1135238004001009904「【管理后台】新增批量导出/上传多话术文案的工具」。

话术同事日常要跨几十个话术统一改文案（活动换期、口径调整、合规措辞替换），现在只能进每个话术逐条改。需求在**管理后台**话术工具集加卡片「话术文案批量修改」，页内分「文案导出」「文案上传」两 tab：按话术ID + 数据版本 + 筛选条件导出 xlsx 推下载中心，改完回传，后端按「话术ID + 文案ID」定位替换写入**草稿**，只有内容真变了的话术才置【草稿未发布】。

本方案**只覆盖前端（ai-admin-ui）**。

三方口径来源：TAPD 文档（2026-08-19 08:51，最新）、Figma `aeS4cSEEqmi7BdSdlhyhdt` page `6022:2161`、接口文档 `multi-template-content-batch-api.md`。冲突处见「已定口径」。

## 核心形态：同步只做快校验，其余全异步走消息中心

划线原则（需求 §4.3）：**能否不打开文件、不全表扫描就判完**——能则同步即时反馈，不能则异步执行、结果写消息中心。

| 环节 | 校验项 | 时机 | 反馈 |
|---|---|---|---|
| 导出 | 话术ID 必填、去重后 ≤50 | 前端同步 | 弹窗 |
| 导出 | 话术ID 存在性 | 后端同步 | 弹窗，一次性列全 |
| 导出 | 是否存在符合筛选条件的文案 | **异步** | 消息中心 |
| 上传 | 文件格式 `.xlsx`、≤10MB、是否已选文件 | 前端同步 | toast |
| 上传 | 表头必需列、数据行数、逐行全量校验 | **异步** | 消息中心（带详情） |

前端**不解析 xlsx**，不引解析库。

## 已定口径

**接口 vs 设计稿** —— 上一版的阻塞项（结果弹窗没有数据来源）已由本次变更解除：那 4 张结果画板不再是工具页内的同步弹窗，而是**消息中心的详情弹窗**，数据来自落库的结果详情。

**TAPD vs 设计稿** —— Figma 只更新了导出 tab（加单选组、改 toast 文案、删「无符合条件」画板、修上传成功列头），上传相关的 6 张画板全部停在旧版。以下按 TAPD 走：

| 项 | 按 TAPD | Figma 现状 |
|---|---|---|
| 单选组标签 | 「数据版本」 | 写成「指标维度」（笔误） |
| 单选组默认值 | 默认「已发布数据」 | 默认选中「草稿数据」（笔误） |
| 已识别 N 个话术ID | 输入框下方实时提示，去重时追加「已自动去重 N 个」，>50 转红追加「（超出上限 50 个）」 | 未画，只有静态蓝条 |
| 超 50 个 | 独立弹窗「话术ID数量超出上限」 | 未画 |
| 结果弹窗宿主 | 叠在**消息中心抽屉**之上 | 4 张画板仍叠在工具页上 |
| 上传态 tab | 「文案导出 \| 文案上传」，高亮跟随 | 4 张结果画板仍是颠倒 + 高亮错 |
| 顶部说明条第 3 条 | 「无论导出的是哪个版本，上传的改动一律写入草稿；仅文案实际发生变化的话术会被置为【草稿未发布】」 | 全部 6 张画板仍是旧文案 |

**HTML 原型 vs Figma** —— 原型（TAPD 附件，已随本次变更更新）比 Figma 新，上传 tab 两者不一致。**按原型走**，它与 TAPD 自洽：

| 项 | 按 HTML 原型 | Figma |
|---|---|---|
| 分节标题 | 有「一、上传修改后的文案表格」+ 必填标签「* 文案表格」 | 无，直接是上传区 |
| 上传区首行 | 「将文件拖到此处，或点击上传」 | 「点击上传文件或将文件拖拽到此区域」 |
| 上传区末行 | 多一行「提交后校验与替换在后台进行，**结果在消息中心通知**」 | 无 |
| 主按钮位置 | 面板**外左下** | 面板内右下 |

导出 tab 两者一致，无需裁决。

**保留 Figma 的**：上传区选中文件后**上传区保留、文件行挂下方**（TAPD 写「替换为文件行」，按设计稿）。

**宿主已确认（用户 2026-08-19 口头确认）**：`表头校验不通过`(`6028:25568`)、`数据校验不通过-1`(`6046:27640`)、`数据校验不通过-2`(`6046:27721`)、`上传成功`(`6046:27846`) 这 4 张画板的**弹窗内容原样保留**，只是触发入口从「工具页内提交后同步弹出」改为「**消息中心列表行的【查看详情】点出来**」。画板背景那层工具页只是旧的绘制语境，实现时忽略。

**设计空白：消息中心那一侧没有设计稿。** Figma 挂的 3 张参考截图都是原型上传 tab 的前端 toast 演示（非 .xlsx / 超 10MB / 未选文件），没有一张画消息中心列表、【查看详情】按钮位置、或详情弹窗叠在抽屉上的样子。弹窗**内容**照搬上述 4 张画板即可，但**入口位置与叠加形态无参照**，按现有 `MessageCenter.vue` 表格操作列的惯例实现（与既有【查看详情】/【下载失败数据】/【删除】同排）。

## 接口契约

`src/api/uri.js` 「话术工具集」段（约 L868-L898）末尾追加，前缀用已有的 `dialogueAggre`（`api/uri.js:20`）：

```js
// 话术文案批量修改
export const MULTI_TEMPLATE_CONTENT_BATCH_DOWNLOAD = dialogueAggre + '/template-content/multi/template/batch-download'
export const MULTI_TEMPLATE_CONTENT_BATCH_UPDATE = dialogueAggre + '/template-content/multi/template/batch-update'
```

**导出** `POST batch-download`，`application/json`，无业务响应体（异步）：

| 字段 | 类型 | 前端来源 |
|---|---|---|
| `templateIds` | Long[] | 话术ID 文本框切分去重后的数组，必填 |
| `keyword` | String | 语句输入框，空则不传 |
| `draft` | Boolean | **数据版本单选**：已发布 → `false`（默认），草稿 → `true` |
| `minLastUsedTime` | String | 时间区间起，`yyyy-MM-dd HH:mm:ss` |
| `maxLastUsedTime` | String | 时间区间止，同上 |

时间用 `el-date-picker type="daterange"`，天然一次给两端（后端规则是两端都传才生效），起止补 `00:00:00` / `23:59:59`；未选则两字段都不传。

话术ID 不存在时后端**同步返回业务错误**——需与后端确认 error payload 能否带完整 ID 清单（设计稿要逐条列出 + 计数）。带不了则退化为一行 error toast。

**上传** `POST batch-update`，`multipart/form-data`，字段名 `file`，无业务响应体（异步）。

**结果详情回查（缺）** —— 需求 §4.3「结果详情落库、按消息回查、支持隔天回查」，接口文档里**没有这个接口**。需要后端补：按 `notificationId` 取详情，返回上传四态之一（表头异常清单 / 数据异常分组清单 / 无变更 / 成功统计+受影响话术表）。这是消息中心详情弹窗的唯一数据源，**本期前端的阻塞项**。

## 前端改动

### 1. 工具集卡片入口 — `src/views/scriptTool/scriptTool.vue`

沿用现有 level/type 分发（跟「对话复盘报告」一致，见 [scriptTool.vue:76-86](fontend-code/ai-admin-ui/src/views/scriptTool/scriptTool.vue#L76-L86) 与 [scriptTool.vue:1124-1128](fontend-code/ai-admin-ui/src/views/scriptTool/scriptTool.vue#L1124-L1128)）：

- `level === 1` 卡片列表**末位**追加卡片，标题「话术文案批量修改」、副标题「支持跨多话术的文案导出和上传」，`v-if="hasButtonPermission('script-toolset-copy-batch-modify')"`（权限 key 待与权限中心对齐；`hasButtonPermission` 来自 `src/utils/permission.js`）。
- 新增 `gotoCopyBatchModify()`：`this.level++; this.type = 'copyBatchModify'`。
- `level === 2` 追加 `<template v-if="type === 'copyBatchModify'"><ScriptCopyBatchModify /></template>`。
- 新增 svg 图标放 `src/icons/svg/`（如 `script-copy-batch.svg`）。

返回按钮复用页面已有的 `.nav-header` + `backLevel()`。

### 2. 工具主体 — 新增 `src/views/scriptTool/components/ScriptCopyBatchModify.vue`

结构照搬同目录 `DialogReviewReport.vue`：`.tool-title`（图标 + 主副标题）→ `nf-alert.custom-blue-alert` 顶部说明条（3 条）→ 内容面板。第 3 条按 TAPD 改为「无论导出的是哪个版本，上传的改动一律写入草稿，仅文案实际变化的话术转【草稿未发布】」。

面板内 `el-tabs`：`文案导出` / `文案上传`，两份独立 state，切换不清空。

**文案导出 tab**
- 数据版本：`el-radio-group` + `border`，选项「已发布数据 / 草稿数据」，默认「已发布数据」，必选。
- 话术ID：`el-input type="textarea"`，必填。按 `[,，\n\s;；]+` 切分、trim、去重、去空。
- **已识别提示**（设计稿没画，按 TAPD 做）：输入框下方实时文本「已识别 N 个话术ID」，去重时追加「已自动去重 M 个」，N > 50 转红并追加「（超出上限 50 个）」。用 `computed` 派生，不引额外状态。
- 下方常驻 `nf-alert` 蓝条：「单次最多 50 个话术；重复的话术ID 自动去重」。
- 语句：`nf-input` + `?` tooltip；话术最近应用时间：`el-date-picker` 区间。
- 「导出」按顺序判定：① 为空 → 弹窗「请先输入话术ID」；② > 50 → 弹窗「话术ID数量超出上限」（带 N）；③ 调接口，后端返 ID 不存在 → 弹窗「部分话术ID不存在」。全过 → toast「提交成功，请留意消息中心查看导出结果」，**页面即时放行、不清空表单**。
- 空提交的输入框飘红态（画板 `6025:5680`）用 `el-form` + `prop` 原生校验，与①的弹窗二选一——按设计稿保留飘红，弹窗按 TAPD 补。

**文案上传 tab**
- 分节标题「一、上传修改后的文案表格」+ 必填标签「* 文案表格」（按 HTML 原型）。
- `el-upload drag :auto-upload="false"`，样式参照 [AiCreateDialog.vue:145-168](fontend-code/ai-admin-ui/src/views/ai/template/components/AiCreateDialog.vue#L145-L168) 及其 `:deep(.el-upload-dragger)` 样式段。
- 区内四行文案按原型：「将文件拖到此处，或点击上传」/「仅支持 .xlsx 格式，单个文件不超过 10MB」/「请使用本工具导出的表格修改后上传，仅「文案内容」列的改动会被写入」/「提交后校验与替换在后台进行，**结果在消息中心通知**」。
- 文件行渲染在上传区**下方**：excel 图标 + 文件名 + 大小 + `×` 删除。单文件。
- 前端校验（toast，不请求后端）：非 `.xlsx`「文件格式不正确，仅支持 .xlsx 格式的表格文件」；> 10MB「文件超出大小限制，单个文件不得超过 10MB」；未选文件点提交「请先上传文案表格」。
- 「上传并替换」→ `FormData` 提交 → toast「提交成功，请留意消息中心查看上传结果」→ **清空上传区恢复空态**（防重复提交）。

### 3. 消息中心改造 — `src/views/layout/components/MessageCenter.vue`

现有实现（240 行）：`nf-drawer` + `nf-table`，操作列有【查看详情】(`destroy: row => row.type != 1`)、【下载失败数据】(`type === 4`)、【删除】。`goDetailsFn` 现行为是 **删除该条消息 → `emits('openDownloadCenter')` → 关闭抽屉**。

改动：

- **导出类**：复用现有「关消息中心、开下载中心」路径，但必须**去掉 `delFn(row, false)` 这一步**——需求 §4.3 要求详情与消息同生命周期、支持隔天回查，看一眼就删掉消息与之冲突。需确认现有 `type === 1` 的其他消费方是否依赖「看完即删」，不能一刀切改，按新 type 分支处理更稳。
- **上传类**：新增操作列分支，点击后**不删消息、不关抽屉**，按 `notificationId` 拉详情，在抽屉之上叠加 `CopyBatchResultDialog`。`nf-drawer` 之上叠 `el-dialog` 需确认 z-index，必要时给弹窗设 `:modal-append-to-body="false"` 或显式 z-index。
- **按钮显隐**：无内容可展开的两种结果（导出无符合条件、上传无变更）不展示【查看详情】。复用现有 `type === 4` 的做法——message 存 JSON，用其中的标志位控制（现有代码 `jsonParse(row.message).click`），具体字段名待与后端定。
- 消息标题固定「批量导出话术文案」/「批量上传话术文案」，由后端写入；前端 `i18nMapTranslate(row.title)` 已有兜底，无需改列定义。

### 4. 结果详情弹窗 — 新增 `src/views/layout/components/CopyBatchResultDialog.vue`

放在 layout 下与消息中心同目录（宿主是消息中心，不是工具页）。四张画板共用一套壳：标题栏 + `×` → 蓝色汇总条 → 分组卡片 / 统计块 → 右下【我知道了】。props 驱动，两种模式：

- `mode: 'error'` — `summary` + `groups: [{ title, count, items: String[] }]`，分组标题右侧红色计数。条数多时（`6046:27721` 的 26 项）内容区 `max-height` + `overflow-y: auto`，**不截断、不提供错误明细下载**（需求明确）。表头校验不通过复用同一模式，只是分组只有「缺少必需列」。
- `mode: 'success'` — 蓝条 + 三个数字统计块（替换文案条数 / 涉及话术数 / 未变更跳过行数）+ 受影响话术表（话术ID、话术名称、替换条数、当前状态，状态为橙色 tag【草稿未发布】）。

异常条目（`第 45 行 · 文案id：12345656，话术 115940 内不存在此文案id`）设计为**后端返回整串**，前端只做分组渲染——后端加校验类型不波及前端。

**消息内容与详情的数字必须一致**（需求明确：消息说 26 项，点进去就该恰好 26 项），前端不做二次截断。

### 5. 文案

工具集里新加的同类工具（对话复盘报告、LLM个性标签）都直接写中文字面量，不走 i18n。本工具跟随，不动 `src/lang/`，也就不触发 `addLang`。消息中心已有的 i18n key 不动。

## 阻塞与待确认

1. **结果详情回查接口缺失** —— 消息中心详情弹窗的唯一数据源，接口文档里没有。没有它，第 3、4 节只能写组件不能接线。**优先跟后端要**。
2. **导出「话术ID不存在」的 error payload 结构** —— 能否带完整 ID 清单 + 计数。带不了则那张画板落不了地，退化为 error toast。
3. **消息 type 值与 message JSON 结构** —— 上传类/导出类各用哪个 `type`，JSON 里用什么字段标识「有无详情」。需与后端约定，前端才能写操作列的 `destroy` 判断。
4. **改动现有 `goDetailsFn` 的删消息行为** —— 要确认现有 `type === 1` 消费方，避免波及其他业务的消息。
5. **权限 key** `script-toolset-copy-batch-modify` 与权限中心对齐。
6. ~~弹窗宿主~~ —— 已确认：4 张弹窗内容不变，改由消息中心【查看详情】点出。消息中心那一侧仍无设计稿（按钮位置、叠加形态），按现有表格操作列惯例实现，视觉上可能需要产品事后微调，但不影响开工。
7. **Figma 待修**（不阻塞开发，按 TAPD + 原型实现即可，但建议同步产品，免得后面对稿扯皮）：单选组标签「指标维度」应为「数据版本」、默认值应为「已发布数据」；6 张画板顶部说明条第 3 条仍是旧文案；4 张结果画板的宿主应改为消息中心抽屉、tab 顺序与高亮修正；「部分话术ID不存在」画板的 toast 仍是旧的「导出成功，请到下载中心查看」，且示例数字自相矛盾（「共提交 1个，其中 2个不存在」，下面列了 2 条）；上传 tab 与 HTML 原型不一致（分节标题、区内文案、按钮位置）。
