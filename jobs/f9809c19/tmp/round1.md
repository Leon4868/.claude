## 我的核心判断

**这不是一份 PRD，是一份披着 PRD 外壳的技术方案书。** 全文 535 行里，真正描述"用户遇到什么问题、现在怎么解决、有多痛"的内容为零。

## 具体问题

**1. 没有任何现状实证。** 全文没有一个真实用户画像、没有一条现状数据：现在做一张广告素材要多久？谁做？一个月做多少张？外包花多少钱？返工率多少？没有这些，第 16.4 节把所有业务指标推给"各场景在 PoC 前设定基线与目标"——PRD 最该定的东西被延后了。阶段 1 交付完，凭什么判断成功？

**2. 阶段 1 的范围与 4~6 周严重不匹配。** 15.2 要求在 4~6 周内交付：两端入口 + 模型网关 + 密钥托管 + 模型目录 + Prompt 版本化 + 调用日志 + 额度 + 成本 + 文生图 + 参考图生成 + 两个逻辑模型 + 异步任务引擎 + 项目 + 资产 + 通知 + 内容安全。这是 16 个子系统。而第 18 条第 10 项才把"研发团队人数"列为待确认——在人力未知的情况下写死排期，这个排期是虚构的。

**3. P0 = 全部，等于没有优先级。** P0 覆盖 6.1/6.2/6.3/6.5/6.6/7.1/7.2/7.3/7.7/7.8。真正的 MVP 应该是：一个部门、一个场景、一个模型、能看到花了多少钱。额度硬限额、成本分摊、Agent 灰度回滚、Prompt A/B 测试，都是有量之后才成立的问题。

**4. "公共能力底座"是在只有一个真实用例时下的架构赌注。** 抽象的正当性来自第二、第三个用例暴露出的重复。现在只有 AI 创意一个场景要落地，却先定义了 Agent 中心 / Workflow 中心 / Tool 中心 / RAG / 评测 / 模型网关六大公共能力和 14 张核心表（含 `workflow_definition`、`agent_version` 快照）。风险很具体：底座是按**想象中**的客服和风控需求设计的，等真做客服时发现不匹配，改底座的代价远高于当初直接写死。

**5. 文档内部有三处自相矛盾：**
   - 5.1 说"不建议过早拆成大量微服务"，但同一节要求"模型调用、异步任务、高风险风控运行单元可独立部署"，第 14 章又建议"Java 承载业务治理 + Python 承载 AI 运行时"。阶段 1 就引入跨语言双栈 + 独立 Worker + 独立风控运行单元，这已经是分布式系统了，和"不过早拆分"直接冲突。
   - 2.2 非目标写"第一期不建设完全开放的万能多 Agent 平台"，但 7.2 把 Agent 中心列为 P0，要求创建/复制/测试/发布/灰度/回滚/下线 + 12 项配置（模型策略、Prompt 版本、知识库、工具、工作流、记忆策略、输出 Schema、审批策略、内容安全、可见范围、额度、发布版本）。这就是万能 Agent 平台。
   - 15.2 把"内容安全"塞进 4~6 周的阶段 1，而 13.1 定义的内容安全包含数据分级、敏感信息检测、Prompt 注入防护、文件病毒扫描、跨境合规——这本身就是一个季度的工作量。

**6. 额度/成本模型有实操漏洞。** 10.2 说"创建任务并预占额度"。图片生成可按张数×单价预估，但文本流式输出在请求发出时费用不可知——PRD 用同一套"预占-校正"覆盖两类，没说文本场景预占多少、按什么估。另外 7.7 要求"历史账单按调用时价格计算"，但第 11 章的 `quota_usage` 没有价格版本字段，`ai_model` 只有"价格"没有价格生效区间。

**7. 验收标准不可测。** 16.1"模型密钥不出现在前端、普通配置、日志和数据库明文字段中"——怎么验收？扫描脚本？代码审计？渗透测试？谁执行？16.3"无权限文档不会进入用户召回结果"同理，需要一个越权测试集，PRD 没有定义它。不可执行的验收条款等于没有验收。

**8. 缺失的部分：**
   - 降级体验：模型不可用/额度耗尽时，员工在界面上具体看到什么？（13.2 只说"禁止静默返回伪造结果"，那正确的行为是什么？）
   - 数据生命周期：员工离职后其资产归谁？项目删除后对象存储怎么清理？保留期多久？
   - 跨境合规：9.1 明确说"面向海外市场"生成素材，涉及数据出境和素材落地区域，13.1 只有"区域"两个字。
   - 生成内容的商用版权：9.1 提到"广告投放衔接"，而各模型供应商对生成物的商用授权条款差异极大，PRD 完全没有涉及。
   - 容量数字：13.2 写了 P95 < 1s 的目标，但第 18 条把"峰值并发和月调用量"列为待确认。负载未知时的性能目标是无意义的。

**9. 章节顺序反了。** 第 18 章 10 条待确认里，至少 5 条是决定架构的前提：是否允许内部数据发给外部模型、现有技术栈、峰值并发、部门预算、数据分级规则。这些没定，第 14 章的技术选型表和第 15 章的排期就是空中楼阁。正确顺序是：先做阶段 0，拿到答案，再写第 14/15 章。
